# Engine conformance cases

Each `*.json` file is one case an SDK's worker must satisfy and the engine must
drive the same way.
[`tests/integration/engine_conformance_test.ts`](https://github.com/zuke-build/zuke/blob/master/tests/integration/engine_conformance_test.ts)
in the Zuke repository replays every case through the CLI `main()` against the
scripted fake worker.

| Field        | Meaning                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `manifest`   | The `build.describe` answer, plus the fake worker's per-target script keys (`fail`, `failTimes`, `condition_answer`, `cacheKey_answer`, `failHook`, `sleep_ms`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `list`       | The `targets` and `parameters` that `--list --json` must print for it.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `argv`       | The command line of the run.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `code`       | The exit code of the run.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `calls`      | The engine-to-worker calls the run makes after `build.describe`, in order, as `method [target]`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `answers`    | Optional: the answers the engine gives the worker's own `calls` script, in order, as `method json`. An answer the engine refused is `method error <code> <message>`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `then`       | Optional: further runs in the same state directory, each a fresh worker, with `argv`, `code`, `calls`, `configure`, optional `answers` and `manifest`; `$RUN_ID` in an argv is the persisted run's id.                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `configure`  | The `parameters` every run's `build.configure` call carries.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `files`      | Optional: paths, relative to the case's working directory, the run must have written (what `generate-ci` renders from the manifest's `ci` list).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `engineDies` | Optional, and a different kind of case: the engine dies mid-run. `after` names the call once logged the harness kills the engine process with SIGKILL, and `workerExitsWithinMs` bounds how long the worker's process may remain. Its connection ended with no `run.exit` and no signal, which is all a worker sees of an engine that died, and it must exit on its own; on Windows a Deno child ends with the process that spawned it, so the worker is taken down first there, and the case therefore watches that the process is gone, not how it went. Such a case has no `code`, `calls` or `configure`; the harness runs the real engine entrypoint as a process for it. |

Cases keep their targets sequentially ordered so the transcript is
deterministic; concurrency is proved by the integration tests instead.

## `tool.call`

A body reaches a wrapper's task through `tool.call`, which the fake worker
issues from a target's `calls` list like any other request. Its params are the
`target`, the `package` (the wrapper's name after `@zuke/`), the exact `version`
of its release, the `tasks` object the module exports, the `task` on it and the
`args` as JSON, where an argument that is an object with the single key
`configure` is a settings lambda as data: an ordered list of `[setter, [args]]`
pairs, applied to the task's settings after the worker's environment and
directory. The answer is the command output's `code`, `stdout` and `stderr`, the
JSON of any other result, or `{}` for none. A call of the wrong shape, or a
release, export, task or setter the engine cannot find, is refused with `-32602`
naming it; a task that throws fails the call with `-32000` and its message, as
does a result longer than one line of the protocol; a call the run's cancel cuts
short answers `-32001` `cancelled`.

The `tool_*.json` cases call the workspace `@zuke/deno` wrapper's `eval` task on
the running Deno, so nothing is fetched. Two placeholders keep them static:
`$DENO` stands for the running Deno's path and `$ZUKE_DENO_VERSION` for that
wrapper's release, both substituted by the runner before a case is replayed.
